PROJECT 01 · 招聘管理

智聘 · 结构化招聘系统

从招聘需求审批到入职转正、升职调薪的一体化招聘系统。不同行业的差异通过「行业方案包」配置实现，而不是为每个行业各写一套代码。

时间　2026.09角色　个人项目：调研、产品设计与开发技术　Next.js · TypeScript · Prisma

以下截图均来自本地运行的系统，内置一家制造企业的演示数据。

先调研，再动工

动手前先梳理了招聘从需求到入职的全流程，并横向比较互联网、制造、零售、医疗四类行业在流程、必须收集的信息、评估方式和核心指标上的差异。结论是：流程骨架是通用的，差异集中在「配置」上。

  • 通用引擎 + 配置层 + 行业方案包：阶段名称可以自定义，阶段类型固定，保证不同流程之间的漏斗统计可比。
  • 一个行业 = 一个方案包文件：流程模板、评分卡、岗位模板与面试计划、自定义字段、证照类型、技能库、渠道、淘汰原因，初始化时一键导入。
  • 同一套引擎，不同的流程：制造业普工岗走「电话邀约 → 到厂面试 → 实操测试 → 入职体检」，互联网技术岗则是「简历筛选 → 编程测评 → 技术一面 → 技术二面 → HR 面 → 背景调查」。

一条完整的招聘链路

招聘需求审批→职位与人才库→结构化面试→Offer 审批→入职与转正→升职调薪

把管理规则写进系统

招聘里很多问题不是「没有工具」，而是规则只停留在口头上。这些规则被直接做成了系统行为：

  • 独立评价：面试官提交自己的评价之前，看不到同场其他面试官的意见，避免评分被第一个发言的人带偏。
  • 先审批再招人：招聘需求和 Offer 都要走审批；Offer 薪资超出职位预算时给出提示。
  • 四类角色权限：管理员、招聘专员、用人经理、面试官各自只看到该看的内容，所有操作限定在本企业范围内。
  • 候选人信息合规：记录个人信息授权与保留期限，以及资质证照的有效期。
  • 停留提醒：同一阶段停留超过 7 天的候选人自动进入「需要跟进」。

录用之后：人才发展

招聘不在发出 Offer 时结束。候选人被录用后自动建立员工档案，按生命周期往下走，每一步都有清单和记录。

确认入职→入职清单→培训计划→转正评估（转正 / 延长 / 不予转正）→职级与调薪

数据与 AI 辅助

  • AI 辅助但不依赖 AI：简历解析、生成 JD、人岗匹配、推荐面试题、汇总面试评价；未配置模型时相关按钮自动隐藏，其余功能照常使用。
  • 可切换模型：管理员在页面里填写 API Key，可在 Claude 与 DeepSeek、通义千问、Kimi 等国内模型之间切换，也可以一键关闭 AI。
  • 技术实现：Next.js App Router、TypeScript、Tailwind CSS、Prisma（26 张数据表，SQLite，可换 PostgreSQL）。
